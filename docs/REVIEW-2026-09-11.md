### 3. Enums / discriminants
OracleKind (0–3), SessionKind (0–4) and Status (0–2) are identical in Rust `state.rs`, registry `types.ts`, SDK
`pricing.ts Status` / `ORACLE_KIND`, and keeper `session.ts`. The web uses text (`open/closed/halted`), which the keeper
now maps by index (`db.ts STATUS_TEXT`). The DB stored status as text while the keeper read and wrote numbers; fixed in
`apps/keeper/src/db.ts`. `StatusPill` is consistent with `MarketStatus`.

### 4. Pricing parity (`packages/sdk/src/pricing.ts`, Rust canonical)
Divergences found and fixed:
- **conf term**: TS computed `confMult × floor(conf·10⁴/p) / 10⁴`, giving 0 bps for GLD's normal 0.1% conf. Rust (and the
  registry's "bps per 1% conf") is `ceil(confMult × conf × 100 / p)`, giving +5 bps. The old TS under-quoted every spread.
- **age penalty**: TS floored, Rust rounds up. Clamp condition aligned (`age > half && max_age > half`, `min(age, max_age)`).
- **ask**: TS floored, Rust rounds up.
- **clamp**: TS had no `MAX_SPREAD_BPS = 5000` clamp and threw on price 0 (Rust returns 5000).
- **reserve ratio**: TS ignored coin/USDC decimals and threw on price 0. Now it mirrors `DEC_NUM/DEC_DEN`, saturates at
  u64::MAX, and returns `null` where Rust returns the u64::MAX sentinel.
- **reserve-warn input**: `PegDeskClient` never set `reserveWarn`. It now passes the **pre-trade** ratio (as `trade.rs` does).
  Max age for Halted now uses `max_age_closed` (`state.rs max_age`); before, Halted used the open age.
- u64-overflow cases now throw instead of returning out-of-range bigints. Added ports of `conf_bps`, `normalize_to_1e8`,
  `scale_quote` and `weighted_sum`. `pricing.test.ts` is updated (its old expectations encoded the wrong conf semantics).

### 5. Merkle parity
Rust `merkle.rs`, `sdk/merkle.ts` and old `tests/merkle.ts` use the same algorithm (leaf = keccak(epoch‖wallet‖amount_le),
sorted pairs, odd node carried up). There is now **one implementation**: `sdk/merkle.ts` gained the epoch-scoped API
(`buildEpochTree`, `getProofForWallet`, `leafHash`, `verifyProof`, `proofToArgs`, `toArray32`, `keyBytes`, `toU64`), and
`getProof` accepts either tree shape. `tests/merkle.ts` is a re-export shim (relative import, so ts-mocha needs no path
mapping), and its duplicate keccak was deleted. The keeper imports `buildEpochTree` from `@icemarkets/sdk`.

### 6. Registry ↔ programs
`CreateCommodityArgs` covers every registry param. `scripts/seed-commodities.ts` is rewritten. Before, it never sent a tx,
used the wrong arg names, and set `supply_cap = supplyCapUsd × 10⁶`, which assumed a $1 coin. Now:
- It converts the USD caps using the **live seed price**: `floor(usd·10⁶·1e8 / price_1e8)`. Prices come from Hermes
  `/v2/updates/price/latest` (scaled like `scale_quote`, US-cents aware) for PythPull, `manual-prices.json` for
  KeeperSigned, and `SEED_PRICE_<SYM>` otherwise. Coins with no price are skipped.
- Tier A → `pyth_min_signatures = 0` (Full), B/C → 5 (Partial ≥ 5, per CONTRACTS §1).
- Switchboard's `feed_account` is the KeeperPrice stand-in PDA.
- It runs `initialize_config` if missing, then `set_keepers`, skips existing commodities, and writes
  `deployments/<cluster>.{json,sql}` (the SQL fills the `commodities` rows the keeper needs).

## Open questions

1. **Switchboard coins can't trade yet.** The on-chain stand-in reads a KeeperPrice at `feed_account`, but no keeper cycle
   relays Switchboard values via `keeper_update_price`. Should `oracle.ts` post them (the program already accepts
   Switchboard kind in `keeper_update_price`)?
2. **Payout min-holding filter** is disabled: TWAB is in memecoin units and there is no memecoin USD price. Use
   `trades.price_usd` or the DBC curve price?
3. **Payout epoch resumability.** If push or finalize fails after `open_epoch`, the keeper's next cycle opens `index+1` and
   the stuck epoch waits 180 days for `sweep_unclaimed`. Should the keeper resume unfinalized epochs from the `epochs` table?
4. **Buyback `min_ice_out`** defaults to 1, which is sandwichable. Quote from ICE/GLD reserves, or send via Jito?
5. **Composite (index) coins** are not tradable client-side (the web has no leg remaining-accounts / oracle reads). OK for v1.1?
6. **Indexer ingestion is still TODO** (`webhook.ts`), so `pools`, `trades`, `balance_events` and `payouts` claims are never
   written from chain. Keeper payouts and fees depend on `pools` and `balance_events` existing. Who owns the decoder, and
   when do `pools` rows get their `ticker`/`name` (set by the launch UI or the webhook)?
7. **Closed markets in the UI.** The TradePanel still shows the buy tab; `actions.ts` refuses the buy with a toast. Should
   the UI disable buy while Closed?
8. `.env.example` pairs `SOLANA_CLUSTER=devnet` with a mainnet `USDC_MINT`. The seed script/web fall back to the registry
   devnet USDC only when it is unset.
9. `@icemarkets/registry` has `main: dist/index.js`, so the compiled indexer (`node dist/server.js`) needs `pnpm -r build` first.
   `@icemarkets/sdk` points at `src/` (tsx / Next only). Unify?
